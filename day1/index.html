    Day 1: Mastering the Linux Environment

    1. Workshop Foundation (0:00 - 0:30)

    Purpose of This Workshop

    This workshop helps biologists become confident users of Linux and High-Performance Computing (HPC). The goal is to provide the practical understanding needed to manage, analyze, and interpret large datasets.

    Why Biologists Need Linux

    Modern research generates datasets (NGS, Multi-omics) that are: * Too large for personal computers. * Computationally intensive. * Requiring automation and reproducibility.

    2. Introduction to Linux & Architecture

    Linux is a family of open-source operating systems based on a kernel created by Linus Torvalds in 1991.

    The Layered Structure

    Linux architecture defines how components interact:

    1. Hardware Layer: Physical components like CPU, RAM, and HDD.
    2. Kernel: The "brain" that manages hardware resources and controls communication.
    3. System Libraries: Pre-written code that allows applications to interact with the kernel.
    4. The Shell: The command-line interpreter that serves as a bridge between the user and the kernel.
    5. User & Utilities: Tools for managing software, files, and users.

    3. Linux File Hierarchy Structure (FHS)

    Everything in Linux starts from the Root (/). All files and directories appear under the root.

    Common Directories

    • /bin: Important binary applications (tools).
    • /home: Residential zone where user data lives.
    • /tmp: Temporary storage; files here may be deleted upon reboot.
    • /etc: Control room containing configuration files.
    • /root: The home directory for the administrative root user.

    4. The Linux Shell & Command Anatomy

    When you open the terminal, you are presented with a Prompt: username@hostname:~$.

    Command Syntax

    The basic syntax is: command -options argument. Example: ls -l --sort time Documents/

    • Command: The "Verb" (what to do, e.g., ls).
    • Options/Switches: Change behavior (e.g., -l for long format).
    • Argument: The "Object" (what to act on, e.g., a folder).

    Pro Tip: Spaces are critical. ls-l will fail; ls -l works.

    5. Basic File and Folder Navigation

    Use these commands to move through the "Digital Lab."

    • pwd: Print Working Directory (Where am I?).
    • ls -lhtr: List files in long format, human-readable, sorted by time (oldest first).
    • cd ..: Move up one level in the directory tree.
    • cd ~: Move back to your Home directory.
    • mkdir <dir>: Create a new directory.

    6. View and Manipulate Data

    Inspection

    • wc -l file1: Count the number of lines in a file.
    • head -n 100 file1: View the first 100 lines.
    • tail -n +2 file1: View from the 2nd line (perfect for skipping headers).
    • zcat file.gz | more: Peek into a compressed file page-by-page.

    Data Wrangling

    • cut -f 1,4 file.tsv: Extract the 1st and 4th columns.
    • grep -w 'chr1' peaks.tsv: Search for the exact word 'chr1'.
    • awk '{print $3-$2}' file.bed: Subtract column 2 from column 3.
    • sort -V file1: Perform a version sort (ideal for chromosome names).

    7. Meta Characters & Security

    • Wildcards (*): Match multiple files (e.g., ls *.fastq).
    • Pipes (|): Join commands; output of one becomes input of the next.
    • Redirection (>): Save output to a file.
    • rm -rf <dir>: Danger Zone. Forcefully remove a directory and all its contents.

    8. Reducing Fear and Anxiety

    • Making mistakes is a normal part of learning.
    • You cannot damage the system through normal commands.
    • Users are not expected to memorize commands; use documentation as a reference.
