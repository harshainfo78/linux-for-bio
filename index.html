    # Part 1: The Linux Architecture

Before typing commands, we must understand the environment. Linux is not just one program; it is a layered system.

## The Layered Structure
Linux architecture defines how components interact to manage resources. Think of it like an "onion" with layers.

```mermaid
graph TD
    User((User / Applications)) --> Shell[The Shell: CLI]
    Shell --> Kernel[The Kernel: The Brain]
    Kernel --> HW[Hardware: CPU, RAM, Disk]

    style Kernel fill:#f96,stroke:#333,stroke-width:2px
    style Shell fill:#61dafb,stroke:#333,stroke-width:2px

    1. The Kernel (The Brain)

    The kernel is the core. It manages hardware (RAM, CPU) and prevents conflicts between programs.

    2. The Shell (The Interpreter)

    The Shell is a program that exposes the operating system to you. * It acts as a bridge: You type a command, the shell interprets it, and sends it to the kernel. * The Terminal: This is the text-window you are looking at. The Shell is the program running inside it.

    !!! note "Kernel vs. Distro" The Kernel is the core technology. A Distribution (Distro) (like Ubuntu, CentOS, or Red Hat) is the kernel combined with software packages to make a usable operating system.

    Anatomy of a Command

    When you type in the shell, you follow a specific syntax:

    Command + Options + Arguments

    Example from Source: ls -l --sort time Documents/

    graph LR
    A[ls] -- "Command" --> Action(List Files)
    B[-l] -- "Option/Flag" --> Format(Long Format)
    C[Documents/] -- "Argument" --> Target(Target Folder)

    style A fill:#f9f,stroke:#333
    style B fill:#ff9,stroke:#333
    style C fill:#9f9,stroke:#333
    • Command: What you want to do.
    • Option (Switch): Modifies behavior (starts with - or --).
    • Argument: What the command operates on (a file or folder).

# Part 2: The Filesystem Hierarchy

In Windows/Mac, you see folders. In Linux, we visualize an **Inverted Tree**.

## The Filesystem Hierarchy Standard (FHS)
Everything in Linux starts at the **Root** directory, represented by a forward slash `/`. 

!!! warning "Root vs. Root User"
    *   `/` is the **Root Directory** (the start of the filesystem).
    *   `/root` is the home folder for the administrator user.
    *   They are different!

### Visualizing the Tree
According to the FHS, specific directories serve specific functions.

```mermaid
graph TD
    Root["/ (Root)"] --> Bin["/bin <br>(Binaries/Apps)"]
    Root --> Home["/home <br>(User Folders)"]
    Root --> Var["/var <br>(Logs/Data)"]
    Root --> Tmp["/tmp <br>(Temporary)"]

    Home --> User1["/home/ibdc"]
    Home --> User2["/home/rcb"]
    Home --> User3["/home/ucsd"]

    style Root fill:#ef5350,stroke:#333,stroke-width:2px

    Key Directories for Biologists

    • /home: Where your personal data lives. If you log in as ibdc, you land in /home/ibdc.
    • /bin: Where commands like ls and cp live.
    • /var: Variable data (log files).
    • /mnt or /media: External hard drives.

# Part 3: Navigation & Basic Operations

**Goal:** Learn to move around the "Tree" and create files.

## 1. Where am I? (`pwd`)
You are always in a "Current Working Directory." To see it, type:
```bash
pwd
# Output example: /home/ibdc
    • /home is the parent folder.
    • ibdc is your current folder.

    2. Moving Around (cd)

    To change directories, use cd. You can use Absolute or Relative paths.

    Path Type Definition Example
    Absolute Full address starting from Root /. Always works. cd /home/ibdc/data
    Relative Directions starting from here. cd data

    Critical Shortcuts

    • cd ~ : Teleport straight to your Home directory.
    • cd .. : Move Up one level (from /home/ibdc to /home).
    • cd - : Go back to the previous folder you were in.

    3. Listing Files (ls)

    To see what is in a folder. Options allow you to see details.

    • ls : Simple list.
    • ls -l : Long format (shows size, date, permissions).
    • ls -lt : Sort by Time (newest first).
    • ls -a : Show All (including hidden files starting with .).

    4. Creating & Manipulating

    Now that we can move, let's touch data.

    • Create Folder: mkdir new_folder
    • Create Empty File: touch file.txt
    • Copying:
      • cp file.txt copy.txt (File copy)
      • cp -r data_folder/ backup_folder/ (Recursive copy for folders)
    • Moving/Renaming:
      • mv file.txt /tmp/ (Move to tmp)
      • mv old.txt new.txt (Rename)

    !!! danger "Deleting Files" The rm command deletes files permanently. * rm file.txt deletes a file. * rm -r foldername deletes a folder and everything inside it.

# Day 1 Cheat Sheet

*Derived from "Essential Guide to Linux Terminal Commands"*.

## Navigation
| Command | Action |
| :--- | :--- |
| `pwd` | Show current directory path |
| `cd /` | Go to Root directory |
| `cd ~` | Go to Home directory |
| `cd ..` | Go up one level |
| `cd -` | Go to previous working directory |

## Listing & Files
| Command | Action |
| :--- | :--- |
| `ls -lh` | List files with details + human readable sizes (KB/MB) |
| `ls -t` | List sorted by time (newest first) |
| `mkdir [name]` | Create a new directory |
| `cp -r [src] [dst]` | Copy a directory recursively |
| `mv [src] [dst]` | Move or Rename a file |
| `rm -r [dir]` | Remove a directory (**Permanent!**) |

## Shortcuts
| Key | Action |
| :--- | :--- |
| `Tab` | Autocomplete file names |
| `Ctrl+C` | Stop/Kill the current command |
| `Ctrl+L` | Clear the screen (same as `clear`) |
| `Up Arrow` | See previous commands |
